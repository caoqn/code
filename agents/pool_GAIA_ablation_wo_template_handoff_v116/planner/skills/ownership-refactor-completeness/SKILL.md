---
name: ownership-refactor-completeness
description: Checklist for centralizing authenticated resource ownership checks across API endpoints
trigger: When replacing duplicated user/resource ownership validation with a shared service helper
---
1. Inventory every endpoint that reads, updates, deletes, or transitions a user-owned resource; inspect service and repository layers for existing checks.
2. Define one canonical helper with the exact required signature, synchronous/asynchronous behavior matching the database session, and model-agnostic typing.
3. Preserve data-access not-found semantics: do not swallow or convert repository 404 exceptions; ensure a missing `None` result follows established caller behavior.
4. Define the permission exception in the designated API error module (or make the shared exception importable there), and register a dedicated handler returning the exact required status and JSON payload.
5. Wire the helper into each relevant endpoint flow before mutation/serialization, passing the concrete model class; do not merely import or instantiate an unused service.
6. Remove old inline owner comparisons and unused imports, then grep all target files for residual checks and helper call coverage.
7. Verify application startup registration, compile every changed file, and run direct behavior tests for owner match, mismatch, missing resource, sync/async session variants, and all CRUD endpoint paths where dependencies permit.
8. Check the final artifact tree for duplicate helper modules, markdown fences, generated bytecode, and accidental truncation; summarize any environment-limited tests explicitly.
